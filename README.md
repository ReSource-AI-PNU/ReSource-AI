# BYPRO (바이프로)

이전 서비스명은 Re:Source AI입니다. GitHub 조직·저장소 주소와 기존 설계 문서 파일명은 링크 호환을 위해 유지합니다.

**폐기물을 내보내는 회사와 받는 처리 업체를, 양쪽을 대변하는 두 AI 에이전트가 근거를 확인하며 연결합니다**

부산·경남의 사출 중소기업 겸직 담당자는 폐플라스틱 흐름마다 어디로 보낼 수 있는지, 그러려면 업체에 무엇을 확인해야 하는지 모릅니다. 처리 업체는 소량·혼합 물량의 품질과 조건을 확인하는 비용이 물량의 가치보다 커서 받지 않습니다. 그래서 가장 쉬운 혼합 소각이 기본값이 됩니다. BYPRO에서는 배출 기업과 처리 업체가 각자 자료를 올리면 회사 측 AI와 업체 측 AI가 대화해, 흐름마다 맞는 업체와 조건, 비용을 찾고, 계약 검토 담당의 대조와 양쪽 승인을 거쳐 요청서·이행 계획서·위탁 계약서 초안을 만듭니다. 대화와 문서에 나오는 숫자와 법 조항은 근거 저장소에서 확인된 값만 씁니다.

- **운영 주소:** https://rsai-o7xpbty4q5vgs.centralus.cloudapp.azure.com (로그인 없이 "체험하기"로 시연 회사의 찾기 결과를 볼 수 있습니다)
- **설계:** [설계안 v3](docs/ReSource_AI_설계안_v3.md) · **구현 상태:** [설계안 v3 구현 상태](docs/ReSource_AI_설계안_v3_구현_상태.md) · **화면 규칙:** [DESIGN.md](DESIGN.md)

## 어떻게 동작하나

```
배출 기업 자료(사진·영상, 측정값 CSV, 문서)        처리 업체 자료(허가증, 매입 기준표, 수거 지역)
            │                                                │
            ▼                                                ▼
   전문 담당 여섯(판단 도구, 결정적 계산·검색) ── 숫자마다 근거 ID와 계산식
            │
            ▼
   회사 측 AI  ⇄  업체 측 AI   (모델은 근거 ID만 고르고, 근거 검증기·가드레일을 통과한 글만 나감)
            │
            ▼
   계약 검토 담당(규칙 대조 10항목) → 양쪽 담당자 승인 → 요청서 · 이행 계획서 · 위탁 계약서 초안
            │
            ▼
   업체의 반입 검수 기록 → 재활용 실적 리포트, 우리 회사 기록(다음 판정에 반영)
```

- **전문 담당 여섯**은 대회 6단계의 판단 도구입니다. 모델이 아니라 파이썬 함수라 같은 입력에는 늘 같은 결과를 냅니다.
- **회사 측 AI**(Foundry gpt-5-mini)와 **업체 측 AI**(기본 구성: H100의 Ollama qwen2.5:32b, 가용 여부·설정에 따라 Foundry 대체)는 무엇을 묻고 어떤 도구를 부를지, 결과를 어떻게 설명할지만 정합니다. 숫자를 직접 쓰지 못하고, 검증에서 거부되면 한 번 다시 쓰며, 그래도 거부되면 담당자에게 넘깁니다. 대화 하나는 12턴까지입니다.
- **계약 검토 담당**은 모델을 부르지 않는 세 번째 에이전트입니다. 합의 조건을 근거, 업체가 정한 범위, 허가, 수거 가능 지역, 물량·적재, 운반비, 반입 검수, 법령 요건, 지난 검수, 첫 거래 시범 기간과 대조하고, 막힌 합의는 승인할 수 없게 합니다.

## 대회 6단계와 전문 담당

대회 6단계는 화면 맨 위에 진행 막대로 항상 보이고, 에이전트 메시지와 도구 호출은 모두 단계 값을 가진다.

| 단계 | 전문 담당 | 판단 도구 | 하는 일 |
|---|---|---|---|
| ① 식별·분류 | 오염도 판정 | `identify_stream` | 재질·출처(PIR·PCR)·형태를 정리하고 등급을 낸다. 측정값이 사진 추정보다 우선하고, 둘이 다르면 확인 질문을 남긴다. 사진·영상은 H100의 탐지 모델(RT-DETRv2), 사진 속 재질 표기는 OCR로 읽는다 |
| ② 가능성 판단 | 경로 판단 | `judge_route` `judge_reuse` `check_loading` | 허가 품목과 매입 기준을 대조해 매각·위탁 처리·현행 유지·공정 재투입을 판정하고, 최소 물량과 적재(무게·부피)를 검사한다 |
| ③ 규정 검토 | 법률 검토 | `search_clauses` `check_requirements` `match_permit` | 법령 374개 조항에서 원문을 인용하고(BM25F + Azure AI Search + 모델 재순위), 경로별 요건 체크리스트와 허가 품목 대조를 한다. 허가가 맞지 않으면 대화를 열지 않는다 |
| ④ 업종·기업 탐색 | 업체 탐색 | `find_vendors` | 허가 품목, 매입 기준, 도로 거리(카카오)로 가입 업체를 고르고 걸러진 이유를 남긴다. 공공 허가 명부(3,152곳)와 같은 산업단지 등록공장에서 가입하지 않은 후보도 찾는다 |
| ⑤ 비용·탄소 비교 | 비용·탄소 | `cost_carbon` `route_extra_cost` | 매입액, 운송비, 현행 대비 월 손익과 탄소(처리 방식 변화 + 트럭 운송 배출)를 계산하고, 업체 노선에 정류장을 더할 때 늘어나는 비용을 구한다 |
| ⑥ 최적안 제안 | 배정 최적화 | `optimize_assignment` | 폐기물마다 업체·현행 유지·재투입 가운데 회사의 월 순비용(탄소는 KAU 시세로 환산)이 가장 낮은 조합을 OR-Tools CP-SAT으로 고르고, 조합이 적으면 완전 탐색으로 다시 확인한다. 합의 전 단가 협상을 한 번 한다 |

## 주요 기능

| 기능 | 내용 |
|---|---|
| 찾기와 AI 작업실 | 찾기가 도는 동안 전문 담당 여섯, 회사 측 AI, 업체 측 AI를 캐릭터로 보여 주고, 실시간 진행(SSE)과 대화 패널을 함께 둔다 |
| 발표 화면 | 끝난 찾기의 저장된 기록을 전체 화면으로 다시 재생한다(잠시 멈춤, 빠르기, 처음부터). 지어낸 대사나 숫자는 없다 |
| 결과 한 장 | 폐기물별 배정, 월 손익, 탄소, 허가 확인 상태(넷), 확인할 것. 모든 숫자는 누르면 근거가 열린다 |
| 자원순환 효과 | 온실가스 감축량, 전 과정 에너지 절감량, 신재 대체량을 따로 보이고, A~D 시나리오(최적안·개별 처리·현행 유지·전부 매립)를 비교한다. 자료가 없으면 0이 아니라 산정 보류다 |
| 가입하지 않은 업체 | 공공 허가 명부 후보와 2024년 처리 실적, 견적 요청서(복사·메일로 보내기). 앱은 직접 보내지 않는다 |
| 같은 단지 자원순환 후보 | 같은 산업단지 안에서 재생원료를 만드는 곳과 쓸 수 있는 곳을 실제 건물 평면도 위에 보인다 |
| 승인과 서류 | 계약 검토 담당의 검토, 양쪽 승인, 요청서·이행 계획서·위탁 계약서 초안 |
| 재활용 실적 | 업체의 반입 검수 기록으로 만든 실적 리포트(인쇄·CSV). 탄소는 검수 당시 고정한 기준으로 계산한다 |
| 우리 회사 기록 | 지난 계약 검토와 검수 기록을 모아 보이고, 담당자가 승인하면 다음 업체 선택과 예상 단가에 반영한다 |
| 업체 정보 AI 도우미 | 업체가 가입하면 업체 측 AI가 대화로 허가·매입 기준 초안을 만들고, 담당자가 확인한 항목만 저장한다. 매입 기준표 PDF도 AI가 읽고, 업체 MCP 연결 키로 외부 에이전트가 입력할 수 있다 |
| 보관장 3D 스캔 | 휴대폰 영상으로 보관장을 3D로 재구성해(H100, VGGT·MoGe-2) 더미별 부피·무게와 정리안을 낸다 |
| 공개 신뢰 페이지 | `/trust`에 실제 모델 평가 결과를 공개한다 |

## 평가 (실제 모델, test-v1)

아래는 각 평가일의 모델·시험셋으로 얻은 결과이며, 현재 전체 기능의 정확도나 운영 보장을 뜻하지 않습니다.

자세한 방법은 [평가 설계](docs/평가_설계.md)에 있다.

- 나간 글의 근거 없는 숫자 0/378, 첫 초안 근거 검증 통과 0.972, 끝까지 맞게 마친 비율 0.886, 조직 간 노출 0, 표적 공격 성공 0 (2026-11-18, Foundry gpt-5-mini)
- 업체 측 시험셋 20사례: qwen2.5:7b 10/20, qwen2.5:32b 20/20, Foundry 19/20
- ③ 조항 검색 nDCG@10 0.792, MRR 0.843 (80질의, 낱말 수 세기 0.138에서 개선)
- 기대값은 전문가 검토 전 초안이다. 미달 지표(말만 바꾼 입력의 일관성 0.85, 네 번 모두 맞는 비율 0.614 등)는 [구현 상태 8장](docs/ReSource_AI_설계안_v3_구현_상태.md#8-알려진-문제)에 있다

## 기술 스택

- **에이전트:** 회사 측·업체 측 두 AI(A2A 대화), 판단 도구 MCP 서버, 규칙 기반 계약 검토 담당. 회사 측은 Microsoft Foundry(gpt-5-mini), 업체 측은 Azure ML H100 계산 인스턴스의 Ollama(qwen2.5:32b)이고, H100이 꺼져 있으면 Foundry가 대신 답한다
- **근거 강제:** 근거 저장소(PostgreSQL)와 근거 검증기, 업체 가드레일, 정보 노출 검사, Azure AI Content Safety(Prompt Shields). 계산값에는 출처와 계산 근거를 붙이고, 팀 가정값은 가정으로 구분한다
- **검색:** 로컬 BM25F, Azure AI Search(하이브리드·시맨틱), Foundry text-embedding-3-small, 모델 재순위
- **최적화:** OR-Tools(CP-SAT 배정, 노선 계산), 카카오모빌리티 도로 거리
- **비전:** RT-DETRv2 탐지(H100), Azure AI Document Intelligence(문서 추출, 재질 표기 OCR), VGGT-1B·MoGe-2 3D 재구성(H100)
- **백엔드:** FastAPI (Python)
- **프런트엔드:** Next.js 16, React 19, Tailwind, three.js, PWA
- **운영:** Central US VM 한 대의 Docker Compose(Caddy HTTPS, frontend, backend), Key Vault, Blob Storage, Bicep, GitHub Actions(CI). App Service는 할당량이 없고 Container Apps는 공급자 미등록이라 VM으로 대신했다

## MVP 범위 (대회 시연)

- 대상: 녹산산단 PP 사출 중소기업의 겸직 담당자. 압출·필름 공정은 비목표다
- 입력 세 경로: 사진·영상, 측정값 CSV, 문서(허가증, 매입 기준표, 원자재 명세). 보관장 3D 스캔을 더했다
- 시연 장면: (주)한빛정밀(가상)의 흐름 네 개(스프루·러너, 불량 성형품, 퍼지·색 혼합, 원자재 포장 필름)와 처리 업체 세 곳((주)새길자원, (주)남해열분해, (주)미소환경). 시연 숫자는 미리 정하지 않고 판단 도구가 근거 저장소의 값으로 계산한다
- 묶음 수거: 이웃 기업을 모으지 않는다. 업체 측 AI가 자기 노선 안에서 묶는다
- 승인: 계약 검토 담당이 막지 않고 양쪽 담당자가 승인해야 서류가 나온다. 실제 계약, 실제 발송, 신고서 제출은 하지 않는다
- 재학습: 사람 교정과 업체의 실제 결과를 쌓고, 배포 게이트로 판단한다. Azure ML 재학습 작업은 작성만 했다
