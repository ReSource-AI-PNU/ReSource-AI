# 5단계: 초기 Zoom Out 리뷰 보고서

- 대상: `docs/ReSource_AI_설계안_v2.md` 1~616행 전체
- 리뷰어(Goldfish, 대화 기록 없음): egm-zoom-out(기준: zoom-out-standard), egm-inventive-catalyst
- 두 리뷰어 모두 완료했다. 각 리뷰어의 원문 판정을 줄이되 근거와 행 번호는 유지했다.
- 검토 요청자가 지정한 추가 관점: 실제 사용자 장면, 핵심 문제의 초점, Azure 자원의 실제 사용 가능성
- 정정: Zoom Out 리뷰어가 `context/구현_현황.md`의 "프런트가 백엔드 API 하나만 호출한다"를 바로잡았다. 실제로는 `/feasibility/preview`와 `/c/questions` 두 개를 호출한다. 사실 자료를 고친 뒤 6단계로 넘어갔다.

## A. egm-zoom-out (Blocker 1, Major 12, Nit 6)

- 맥락 충분성은 통과했다. 목표(46행)와 사용자가 잃는 것(71행)이 분명하다.
- 총평: 한 줄 정의는 좁지만 본문이 그보다 훨씬 넓다. 시연 손익 개선의 3분의 2는 가장 단순한 경로(스프루 재투입)에서 나오고, 가장 복잡한 장치(묶음 매칭, 이웃 화면, 업체 화면, A2A, 공동처리 신고서)는 가장 작은 효과(월 9만 원)를 위해 존재한다.

### ZO-1 [Blocker] 설계의 중심 노드와 3개 단계가 확인되지 않은 Azure 자원 위에 있다

- 행: 151, 155, 157, 158, 160, 169, 174, 195, 197, 202~203, 223~224, 552, 568, 578, 598, 605, 446~454
- **확인된 자원**: Foundry 모델 배포, Foundry Tools Speech, Entra External ID, Blob(부분 확인).
- **확인되지 않은 자원**: Azure ML 작업 영역·엔드포인트(대회용 사용과 GPU 할당량), Foundry Agent Service, AI Search, Document Intelligence, Fabric, PostgreSQL Flexible, Container Apps, Application Insights, Content Safety, Bicep(리소스 그룹 신규 생성 금지와 충돌 가능).
- **문제**: 다음이 모두 미확인 자원 위에 놓여 있다.
  - 조정 에이전트(197, 552행). 모든 요청이 이곳을 지난다.
  - ② 경로 판정(598행), ③ 규정 검토(568행), ⑤ 비용·탄소(605행)
  - 백엔드 호스팅(Container Apps)과 DB(PostgreSQL)
- 실행 환경 절과 대체 경로가 문서에 없다.
- 대회 공지 원문이 없어 Microsoft 기술 사용이 심사 항목인지도 확인되지 않는다.
- **권고**
  - 4장 앞에 실행 환경 절을 두고 자원을 "확인됨 / 확인 필요 / 없을 때의 대체"로 나눈다.
  - 확인된 자원만으로 MVP가 끝까지 돌게 한다.
  - 조정은 FastAPI 안의 순차 함수로 둔다. LLM은 ③, ⑥, 되묻기에만 쓴다(475행 원칙과 일치).

### ZO-2 [Major] 겸직 담당자: 되묻기와 작업 시간에 상한이 없다

- 행: 75, 111, 253~258, 410~419, 435, 437, 479
- **문제**

  - 걸으며 진단은 모바일 장면인데, DESIGN.md는 데스크톱 2열 배치만 정의한다.
- **권고**: 백엔드 `docs/c-track/question-policy.md`의 "질문 최대 3개씩 최대 2묶음" 정책을 설계의 되묻기 규칙으로 가져온다.

### ZO-3 [Major] 이웃 기업: 묶음 상대의 흐름 물량이 어디서 오는지 없다

- 행: 52, 120~121, 204, 256, 356, 415, 425, 450

  - 이웃이 언제, 왜 자기 물량을 미리 입력하는지가 설계에 없다.
- 결과적으로 킥 장면은 가상 데이터로만 성립한다.

### ZO-4 [Major] 이웃 기업: "배출량 숨기고 분담 비율만 공개"가 산수로 깨진다

- 행: 284, 356, 415, 425, 482
- **문제**

- **권고**: 각 사에는 "내 분담액"만 보이고, 게이지는 참여사 수만 표시한다.

### ZO-5 [Major] 수거 업체: 업체 화면, A2A, 실제 결과 기록을 할 동기가 없다

### ZO-6 [Major] 기능이 다섯 문제와 네 차별화 기능으로 흩어져 있다

- 행: 83~89, 286~291, 421~440, 446~454

  - MVP는 "흐름 입력 → 흐름별 갈 곳과 손익 → 이행 계획서와 업체 견적 요청"으로 줄인다.

### ZO-7 [Major] 손익 전환의 3분의 2가 검증되지 않은 가정 1에 기댄다

- 행: 312, 339, 343~345, 413
- **계산**: 월 개선 982,500원의 구성은 스프루 660,000원(67%), 불량품 190,000원, 필름 90,000원, 퍼지 42,500원이다.
- **문제**

  - 단서대로라면 개선 폭은 월 약 32만 원으로 줄어든다.
- **권고**: 가정 1을 확인하기 전에는 기준선을 "스프루는 이미 재투입"으로 둔다. 그러면 무게중심이 혼합·오염 흐름으로 옮겨 간다.

### ZO-8 [Major] 가장 복잡한 묶음 장치가 가장 작은 효과를 낸다

- 행: 168, 204~205, 256, 271, 276~284, 347, 351~352, 356, 415, 481, 569~570, 601~603
- **문제**
  - 묶음의 기여는 시나리오 A와 B의 차이인 월 90,000원(개선의 9%)뿐이다.
  - 화면 손익은 고정 50원/kg으로 계산해서, OR-Tools와 Azure Maps의 결과가 숫자에 쓰이지 않는다.
  - 같은 업체가 불량품도 가져가므로, 필름을 같은 차에 실으면 이웃 없이도 적재율 70%다.
  - 271행 규칙대로라면 적재율 40%인 불량품도 단독 매각이 안 되는데, 코드는 PCR에만 검사를 적용한다. 규칙이 시연 결과에 맞춰져 있다.
  - 무게 적재율 123%를 쓰면서 481행에는 "필름은 부피가 먼저 찬다"고 적어 서로 모순된다.
- **권고**
  - MVP의 묶음은 "같은 수거 업체에 내 공장 흐름을 합쳐 싣기 + 단지 내 후보 수 표시"로 줄인다.
  - OR-Tools는 뺀다.

### ZO-10 [Major] 투자가 식별에 몰려 있고, 근본 원인(정보 부재)의 데이터는 "약"이다

### ZO-13 [Major] 설계가 새로 제안하는 것 대부분이 이미 다른 형태로 있다

- **이미 있는 구현**

- **권고**: ②⑤ 계산의 정본을 백엔드 하나로 정하고, 탐지는 프로세스 내 추론을 MVP 구조로 명시한다.

## B. egm-inventive-catalyst (Major 8, Nit 2): 진짜 모순이 있다

### IC-1 [Major] 묶음 수거가 "이웃 기업을 플랫폼이 모아야 성립한다"는 전제

- 행: 120~121, 280~284, 415, 425, 437
- **피할 수 있는 타협**
  - 콜드 스타트: 이웃의 흐름 물량이 가상 데이터에만 있다.
  - 동의 사슬이 생긴다.
  - 한 회사의 에이전트가 다른 두 회사의 계약 조건을 정한다(437행). 이는 5.4의 개별 계약 원칙(280행)과 어긋나고, 협상과 동의의 순서도 정해지지 않았다.
- **해법(Inversion, Intermediary)**: 모으는 지점을 수거 업체의 기존 순회 경로로 옮긴다. 요청은 "내 흐름을 단지 순회의 정차지로 넣어 달라"가 되고, 이웃 초대는 경로가 없을 때만 쓰는 보조 수단이 된다.
- **부담**: 업체 경로는 영업 비밀일 수 있다. 업체 의존과 가격 결정력 이동이 생기고, 킥 장면의 연출 효과가 줄어든다.

### IC-2 [Major] "배출량 숨김"이 산수로 깨진다 (ZO-4와 같은 지적)

- **해법(Intermediary)**: 업체가 사업장별로 계량한 값에 kg당 단일 운임을 곱해 회사마다 따로 청구한다. 화면에는 "kg당 운임과 내 청구액"만 보인다. 게이지는 일정 수 이상이 모이면 한 번에 "기준 충족"으로 표시한다.
- **부담**: 단일 운임은 거리 기준의 공정성을 잃는다. 업체가 단일 운임에 동의해야 한다.

### IC-3 [Major] 트럭 적재율 하나가 물리 조건을 대신한다

- 행: 256, 356, 415, 437, 481
- **문제**
  - 데이터 계약에 부피 항목이 없다.
  - "적재율 123%"는 성공처럼 보이지만 실제로는 한 번에 실을 수 없다는 뜻이다.
  - 모의 일정은 월 2회이므로 회당 적재율은 61.5%다.
