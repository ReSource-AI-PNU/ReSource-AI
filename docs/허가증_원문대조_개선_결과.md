# 허가 품목 일치와 허가증 원문 대조 구분 결과 (2026-11-19)

"업체가 입력한 허가 품목이 일치한다"와 "담당자가 허가증 원문을 대조했다"를 가른다. 배정 경로(업체 · 폐기물 품목·재질 · 처리 방식)마다 허가 확인 상태를 넷으로 판정하고, 결과표·승인 카드·법령 요건 제목이 같은 상태를 보이며, 원문 대조가 끝나지 않은 경로는 서버가 확정하지 않는다.

## 2. 판정 규칙

| 상태 | 화면 이름(칩) | 판정 | 언제 |
|---|---|---|---|
| `verified` | 허가증 대조 완료(먹 채움) | 충족 | 배출 기업 담당자가 그 업체가 올린 허가증 원문에서 이 품목과 처리 방식을 대조해 맞다고 기록 |
| `pending_review` | 허가증 검토 대기(`sunken`) | 조건부, 확정 보류 | 업체가 허가증을 올려 AI가 읽었지만 대조 기록이 없음 |
| `registered` | 등록 품목 일치 · 허가증 원본 확인 필요(`warn-bg`) | 조건부, 확정 보류, 문의 후보로는 남음 | 업체 입력, 차고지 근처 같은 상호의 공공 명부, 원문 없는 예전 문서 값 |
| `mismatch` | 이 경로로 진행 불가(`loss-bg`) | 불충족, 배정·대안·합계에서 뺌 | 대조 결과 품목·처리 방식이 다름, 업체가 확인한 허가증 업종이나 공공 명부가 처리 방식과 어긋남 |

- 대조 기록(`POST /sessions/{id}/permit-checks`)에는 문서·쪽·확인한 범위(품목·재질·처리 방식)·누가(조직, bff에서는 계정 이름)·언제가 남고, 근거 패널에서 사람 확인 근거로 열린다. 계정 이름은 배출 기업 화면에만 보인다.
- 기존 저장 데이터: 대조 기록 없는 예전 doc 근거는 "원본 확인 필요"(근거 수준 "업체가 허가증에서 읽은 값(원문 없음)"), 이전 결과의 `registry·document·self`는 화면이 "원문 대조 기록 없음(이전 결과)"으로 그린다.
- 승인을 기다리는 진단은 허가 확인 상태가 바뀌면(허가증 업로드, 대조 기록, 허가 품목 변경) 최적안과 결과를 다시 계산해 결과표·승인 카드·법령 요건이 같은 값을 보인다.
- 수거 가능 여부·운반비(노선 밖 공장 수거, 운반비 포함·별도)는 그대로 쓴다. 대조 결과로 경로가 바뀌면 새 업체의 운반비와 수거 조건으로 다시 계산한다.

## 5. 확인하지 못한 것

- 업체가 올린 허가증 파일은 서버에 남기지 않는다. 배출 기업 담당자는 AI가 읽은 원문 표기와 쪽까지만 화면에서 보고, 원본은 업체에서 받은 사본으로 대조한다. 원본 열람은 파일 보관(저장소·접근 권한)을 따로 만들어야 한다.
- 허가증 PDF를 Document Intelligence로 읽는 경로(쪽 번호를 `pages[].lines`에서 찾음)는 실제 PDF로 돌려 보지 않았다. 시험과 브라우저 점검은 글 파일(한 쪽) 업로드로 했다.
- 대조한 사람의 계정 이름은 bff 모드 시험에서만 확인했다. 로컬 header 모드에서는 조직 이름만 남는다.
- 운영 VM 배포와 운영 데이터의 기존 진단 갱신은 하지 않았다(배포는 오케스트레이션 세션이 맡는다). 이미 승인 대기인 운영 진단은 업체 자료가 바뀌거나 대조를 기록할 때 새 판정으로 다시 계산된다.
- 실제 모델(Foundry·Ollama) 평가는 다시 돌리지 않았다. 평가 세계는 담당자가 허가증을 대조해 둔 상태로 시작하도록 바꿔 허가 확인과 다른 판단이 섞이지 않게 했다.
