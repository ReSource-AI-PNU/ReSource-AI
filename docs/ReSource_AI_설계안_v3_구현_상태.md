# 설계안 v3 구현 상태

작성일: 2026-11-17 (2026-11-19 구현 점검, 배출 사업장 설문, 6단계 보강, 자원순환 판단 평가 대응 반영)

설계안 v3 구현이 어디까지 됐는지, 구현하면서 무엇을 다르게 정했는지 적는다. 설계안 v3 원문 12장의 구현 상태 표는 구현을 시작하기 전(2026-11-16) 기준이다. 실제 상태는 이 문서를 따른다.

상태 표기는 네 가지다.

- **검증됨**: 실행해 테스트로 확인했다. "(배포)"가 붙으면 배포 주소에서도 확인했다.
- **작성됨(미실행)**: 코드는 있지만 실제 서비스로 실행해 보지 못했다.
- **막힘**: 구독 권한이나 공급자 등록 때문에 만들 수 없다.
- **안 함**: 손대지 못했다.

## 1. 한눈에 보기

- 배출 기업과 업체가 자료를 올리고, 회사 측 AI와 업체 측 AI가 대화해 폐기물별 업체 배정과 월 손익, 요청서와 이행 계획서까지 나오는 과정이 **배포 주소(https://rsai-o7xpbty4q5vgs.centralus.cloudapp.azure.com)에서 실제 모델로 돈다.** 회사 측과 업체 두 곳은 Foundry gpt-5-mini, 업체 한 곳(시연의 남해열분해)은 H100 계산 인스턴스의 Ollama qwen2.5:32b가 쓴다(11-19까지는 A10 GPU VM의 qwen2.5:7b). 체험하기는 배포 때 실제 모델로 승인 대기까지 돌린 진단을 보여 주고, 실제 모델이 실패하면 규칙 정책으로 되돌려 둔다.
- 배포는 App Service(할당량 0)와 Container Apps(공급자 미등록) 대신 Central US의 CPU VM 한 대에 Docker Compose로 했다(backend `infra/vm.bicep`, `infra/vm/`). DB와 같은 지역이다.
- 업체 측 오픈 모델은 2026-11-19부터 Azure ML 작업 영역 `team-workspace`의 H100 계산 인스턴스 `rsai-h100`(NC40ads_H100_v5, H100 NVL 94GB, eastus2)에서 돈다. 구독의 VM 할당량에는 H100이 없어 ML 계산 할당량을 썼다. 전용 VNet을 앱 VNet과 피어링했고 Ollama는 사설 주소에만 묶는다. 조직위 요청대로 서비스하지 않을 때 `infra/h100/h100.sh down`으로 끄고, 꺼진 동안 Ollama 차례는 Foundry가 대신 답한다(`OLLAMA_FALLBACK=1`). 시험셋 20사례(업체 측만 바꿈)에서 qwen2.5:7b 10/20, qwen2.5:32b 20/20, Foundry 19/20이었다. 예전 A10 GPU VM(East US)은 할당 해제해 예비로 두고, 맥의 자동 켜기·끄기는 내렸다.
- 백엔드 테스트는 1,503개가 통과하고 5개는 건너뛴다(2026-11-19 main 483aecc. 건너뛰는 것은 PostGIS, Agent Framework, Azure SDK, OpenTelemetry, OpenCV가 필요한 테스트다). 프런트는 단위 시험, 타입 검사, 빌드, 브라우저 E2E(5개 통과, bff 전용 1개 건너뜀)를 통과한다.
- 실제 모델 평가(test-v1, Foundry gpt-5-mini, 2026-11-18): 나간 글의 근거 없는 숫자 0/378, 첫 초안 근거 검증 통과 0.972, 끝까지 맞게 마친 비율 0.886, 조직 간 노출 0, 표적 공격 성공 0. 기대값은 전문가 검토 전 초안이다. 결과는 공개 신뢰 페이지(`/trust`)에 있다.

## 3. 대회 6단계별 상태 (2026-11-19 점검 뒤 보강)

| 단계 | 도는 것 | 남은 약점 |
|---|---|---|
| ① 식별·분류 | 탐지(재질 대분류·상태), CSV, 문서 추출, 등급(측정 우선, 사진 추정), 측정 등급과 사진 등급이 다를 때 확인 질문. **보강:** 기준값 규칙이 낸 등급은 계산(calc) 근거, 시연 사진 오염 비율은 가정값 근거로 바꿔 모델처럼 보이지 않게 했다 | PP와 PE를 사진으로 가르지 못한다. 등급 모델은 실제 등급 데이터가 없어 학습하지 못했다 |
| ② 재활용 가능성 | 매각·위탁 처리·현행 유지·공정 재투입, 측정값이 없으면 조건부, 최소 물량·적재 합산, 민감도. **보강:** 배정마다 처리 방식(재활용·열분해·현행 처리)을 따로 싣고 화면에 보인다. **11-19 평가 대응:** 배정 후보마다 허가 근거 수준을 가른다(허가증·공공 명부 확인 / 허가증 문서 / 업체 입력 / 허가 근거가 맞지 않음). 공공 허가 명부(3,152곳)에서 같은 상호이고 차고지에서 50km 안인 사업장의 업종과 처리 폐기물 분류번호를 대조하고, 명부를 올린 허가 기관과 기준일(한 해 넘게 지났는지)을 적는다. 허가증에서는 업종을 정해 둔 이름으로만 읽어 처리 방식(재활용·열분해는 재활용업, 소각·매립은 처분업)과 맞는지 본다. 업체 입력뿐이면 배정과 법령 요건(받는 업체의 허가)을 조건부로, 근거가 맞지 않으면 그 업체에는 배정하지 않는다. 시연의 (주)미소환경은 허가증 없이 허가 품목만 입력한 업체라 불량 사출품 배정과 그 허가 요건이 조건부로 나온다 | 허가 품목 대조는 품목·재질 이름 일치다. 공공 명부는 상호로 찾으므로 상호를 다르게 올린 업체는 허가증 문서 수준에 머문다. 명부에 영업 상태 열이 없어 허가의 현재 유효성은 명부 기준일까지만 안다 |
| ③ 규정 검토 | **보강:** 법령을 26조에서 374조로(폐기물관리법·시행령·시행규칙·순환경제사회 전환 촉진법). 조항 검색을 낱말 수 세기(nDCG@10 0.138)에서 근거 검색으로 바꿨다(로컬 BM25F 0.617, Azure 연결 시 BM25F+하이브리드·시맨틱 0.621). 그 상위 40개를 gpt-5-mini가 다시 줄 세우게 해 운영 구성이 nDCG@10 0.792, MRR 0.843이 됐다(목표 0.75·0.70 달성, Recall@10 0.786과 답 없음 정확도 0.571은 미달). 경로별 요건 체크리스트 12개(인용 39개는 조문 원문과 일치)로 업체 허가는 판정하고 나머지는 담당자 할 일로 낸다. 결과 화면, 판단 그래프, 이행 계획서에 싣는다 | 별표(보관 기간, 재활용 기준)는 말뭉치에 없다. 담당자 할 일은 서비스가 확인할 수 없다 |
| ④ 업체 탐색 | 가입 업체 탐색과 걸러진 이유, 공공데이터 후보와 견적 요청서. **보강:** 업체가 밝힌 수거 노선이 공장 지역을 지나는지 결과 확인 항목에 넣는다. **11-19 평가 대응:** 공장 → 업체 차고지 거리를 ⑤의 운송 배출로 넘긴다. **11-19 견적 요청서:** 업체 카드에서 그 업체가 후보인 폐기물을 골라 묻는다. 탐색 때 본 흐름 칸을 남기고, 요청서를 만들기 전에 지금 자료로 후보가 맞는지 다시 본다(분류번호·상호·가입 여부·반경). 맞지 않으면 만들지 않고 다시 찾으라고 안내한다(409 `OUTSIDE_STALE`). 알루미늄·금속 스크랩·폐목재는 폐합성수지 재활용업 후보를 내지 않는다. 요청서는 값마다 출처를 적고 거래 방식·kg당 단가·방문 수거·최소 수거량·운반비와 부담 주체·공장이 낼 비용을 넣은 예상 정산을 묻는다(결과 `docs/견적요청서_개선_결과.md`) | 공공 명부 검색은 폐합성수지 재활용업만 다뤄 금속·목재를 받는 업체는 찾지 않는다. 거리는 카카오모빌리티 길찾기 도로 거리다(2026-11-19 연결. 키는 Key Vault의 kakao-rest-api-key이고 호출 허용 IP를 앱 VM으로 묶었다). 호출이 실패하면 직선 × 1.3(가정값)으로 돌아간다 |
| ⑤ 비용·탄소 | 순비용, 탄소, 계약형 현행 처리비 환산. **보강:** 열분해 배출계수 1.239 kgCO2e/kg(Petrík 외 2025, 크레딧 전, 화학 원료 용도, 문헌값)로 퍼지 덩어리도 탄소 합계에 든다. 배출권 시세 환산을 결과 카드에 보인다. **11-19 평가 대응:** 탄소 변화에 운송 배출(환경성적표지 평가계수 트럭 운송 0.192 kgCO2e/ton·km × 월 발생량 × 공장 → 업체 거리)을 더한다. 소각·재활용 계수와 같은 공식 표다. 결과 카드에 처리 방식·운송·거리를 나눠 보이고, 다른 선택지에도 탄소를 붙인다 | 열분해 값은 한국 공식 계수가 아니다. 거리는 카카오 도로 거리이고, 호출이 실패할 때만 직선 × 1.3(가정값)이다. 지금 처리의 운송 배출은 몰라 빼지 않는다. 트럭 계수는 적재율 평균값이라 작은 짐을 따로 실어 가는 경우를 작게 잡는다 |
| ⑥ 최적안 | CP-SAT 배정, 가드레일, 양쪽 승인, 요청서·이행 계획서(단가 조정 조항, 법령 요건), 실제 결과 기록, 실적 리포트, 분리 개선 안내. **보강:** 합의 전 단가 협상 한 번(회사 측 요청 폭 10% 가정값, 업체 측은 가드레일 상한 안에서 답). 시연에서 월 차이 +654,500원 → +681,000원. **11-19 평가 대응:** 배정 목적을 "월 순비용 − 배출권 시세(KAU, t당 29,750원) × 탄소 변화(처리 방식 + 운송)"로 바꿨다. 돈이 같으면 가까운 업체를 고른다. 탄소를 가장 많이 줄이는 배정도 함께 구해 결과에 비교 문단으로 보인다(시연: 불량 사출품을 (주)새길자원에 보내면 한 달 16,000원 줄고 탄소 0.9 kgCO2e 더 줄어(도로 거리 기준) 지금 배정을 골랐다). 화면의 월 손익은 실제로 오가는 돈만 적는다 | 협상은 한 번이고 요청 폭은 가정값이다. 고정 평가셋(test-v1)은 협상을 끄고 잰다 |

| 설문 답 | 구현 |

| 처리비를 차량·횟수 단위로 계약해서 kg 단가를 모른다 | 질문 답과 자료 화면에서 "회당 30만원, 한 달 2번", "월 60만원", "1년에 720만원"을 받아 월 발생량으로 kg당 처리비로 바꾸고, 담당자 입력(human)과 환산(calc) 근거를 남긴다(backend `app/v3/current_cost.py`) |

| 처리비 상승, 소량, 업체 찾기, 견적 왕복, 팔리는지, 법규 근거, 월 손익, 요청서 초안 | 이미 있던 기능으로 대응한다 |

## 6. 구현하면서 정한 것

자세한 계약은 backend 저장소의 `docs/v3/CONTRACT.md`와 `docs/v3/RUNTIME.md`에 있다.

- **근거 ID 형식.** `종류:이름공간:키@판` 꼴이다(예: `law:폐기물관리법:제17조@2026-11-12`). ID를 만드는 코드는 `app/v3/ids.py`에 모았다.
- **모델이 숫자를 쓰지 못하게 하는 방법.** 모델은 값을 직접 적지 않고, 코드가 만든 claim 목록에서 ID만 고른다. 검증기는 자리표시자 밖 숫자를 거부하고, 받는 쪽이 한 번 더 검증한다.
- **핵심 코드는 표준 라이브러리만 쓴다.** 같은 서비스 함수를 표준 라이브러리 HTTP 서버(`python3 -m app.v3.devserver`)로도 띄울 수 있다.
- **두 AI는 판단 도구를 같은 프로세스에서 부른다.** MCP 서버는 같은 도구를 밖으로 내놓는 용도로 따로 있다.
- **인증은 역할 할당 권한이 없어 키 방식이다.** 키는 Key Vault에만 둔다.
- **호스팅은 VM이다.** 되돌리기는 이전 커밋으로 다시 배포하는 방식이다.
- **업체당 대화는 하나다.** 한 업체로 가는 폐기물을 한 대화에 모은다.
- **측정값이 없으면 확정하지 않는다.** 사진 추정 오염 비율과 담당자가 답한 수분만으로는 매입 기준 충족을 조건부로 둔다.
- **합의 뒤 조건이 바뀌면 승인을 막는다.**
- **탄소는 배출권 시세로 환산해 배정에 넣는다(2026-11-19).** 처리 방식이 바뀌어 달라지는 배출과 업체로 실어 가는 운송 배출(트럭 운송 계수 × 월 발생량 × 거리)을 더한 탄소 변화에 배출권(KAU) 시세를 곱해 월 순비용과 함께 본다. 화면의 월 손익은 실제로 오가는 돈만 적고 환산액은 따로 보인다. 탄소를 가장 많이 줄이는 배정과 다르면 그 차이를 결과에 적는다. 배출계수가 없는 처리는 처리 방식 탄소가 합계에서 빠지고(운송 배출은 든다) 화면에 그 사실을 적는다.
- **허가 근거 수준으로 판정을 나눈다(2026-11-19).** 허가 품목이 맞아도 업체가 입력한 것뿐이면 배정을 조건부로 두고, 허가 업종이 처리 방식과 맞지 않거나 공공 허가 명부의 처리 폐기물 분류와 다르면 그 업체에는 배정하지 않는다. 허가증 문서만 있고 명부에서 찾지 못한 업체는 충족이지만 계약 전에 허가 기관에 확인하라고 적는다.
- **가격조사 값은 참고 시세로만 보여 준다.** 손익 계산에는 업체 매입 기준표의 단가만 쓴다.
- **가입하지 않은 업체는 손익과 배정에 넣지 않는다.** 견적 요청서는 만들기만 하고 앱이 보내지 않는다. 초안을 만들거나 복사해도 업체 연락, 견적 확정, 한 달 손익 갱신은 일어나지 않는다(시험으로 저장소가 그대로인지 본다). 시연 자료의 요청서는 복사한 글의 처음과 끝에 시연용 표시가 남는다.

## 7. 가정값과 확인하지 못한 값

- 현행 처리 단가(혼합 소각 250원/kg), A등급과 PET·ABS 등급 상한, 우회 계수, 운행 단가, 최소 물량, 계약 단가 변동 폭은 **팀 가정값**이다. 화면에 "가정값"으로 표시된다.
- 열분해 배출계수, 순환자원 인정 고시, 시행령과 별표는 공식 출처를 확인하지 못해 넣지 않았다.
- 시연 업체와 단가, 체험하기의 지난 거래 검수 기록은 가상이다.
- 사례 50건의 기대값은 전문가 검토 전의 초안이다.

## 8. 알려진 문제

- **③ 규정 검토가 약하다.** 위 3장 참고.
- **체험하기는 실시간 실행이 아니다.** 배포 때 돌린 진단을 다시 보여 준다. 승인과 서류는 지난 거래(가상)로만 보인다.
- **GPU는 맥의 감시 작업에 기대어 켜진다.** 맥이 잠들면 Ollama 차례가 조용히 Foundry로 넘어간다. 시연 전에는 `infra/gpu/gpu.sh up`으로 미리 켠다.
- **실제 모델 실행은 p50 56초, p95 115초가 걸리고, 같은 사례를 네 번 돌려 네 번 모두 맞는 비율은 0.614다**(test-v1, 11-19, pass^1 0.861). 실패 39건 가운데 22건이던 업체 AI의 조건 참조 오류(본문에 쓰지 않은 수거 횟수를 조건에만 가리킴)는 평가 뒤에 고쳤다(backend 29465f7). 정책 위반 19건(게이트 0), 말만 바꾼 입력의 일관성 0.85(목표 0.95), 협상 전술 민감도 0.098(목표 0.01)은 아직 미달이다.
- **담당자가 직접 넣는 이름은 모델 입력에 들어간다.** 나가는 숫자와 조건은 검증기와 가드레일이 막는다.
- 그 밖의 문제는 backend 저장소의 `docs/v3/review-rules.md`와 `docs/v3/static-review.md`에 있다.
