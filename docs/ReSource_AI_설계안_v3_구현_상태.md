# 설계안 v3 구현 상태

작성일: 2026-11-17

설계안 v3 구현이 어디까지 됐는지, 구현하면서 무엇을 다르게 정했는지 적는다. 설계안 v3 원문(12장 구현 상태 표 포함)은 이 저장소에 아직 올라와 있지 않아, 원문 표를 고치는 대신 이 문서를 따로 둔다. 원문이 올라오면 12장에 옮긴다.

상태 표기는 네 가지다.

- **검증됨**: 로컬에서 실행해 테스트로 확인했다.
- **작성됨(미실행)**: 코드는 있지만 실행해 보지 못했다. Azure나 프레임워크 패키지가 필요한 부분이다.
- **막힘**: 구독 권한이나 할당량 때문에 만들 수 없다.
- **안 함**: 손대지 못했다.

## 1. 한눈에 보기

- 배출 기업과 업체가 자료를 올리고, 두 에이전트가 대화해 흐름별 업체 배정과 월 손익, 요청서와 이행 계획서까지 나오는 과정이 **로컬 서버에서 처음부터 끝까지 돈다.** Azure 배포 주소에서는 아직 돌려 보지 못했다.
- 지금 대화를 쓰는 것은 모델이 아니라 **규칙 정책(모델 미연결)**이다. Foundry와 Ollama 모델을 붙이는 코드는 있지만 실제 모델로는 한 번도 돌리지 않았다. 화면에도 그렇게 표시된다.
- 백엔드 테스트는 854개가 통과한다(10개는 FastAPI, SQLAlchemy, MCP, OR-Tools 등이 필요해 로컬에서 건너뛴다).
- 시연 시나리오에서 나간 메시지 15개와 문서 6개는 모두 근거 검증기를 통과했다. 사례 50건의 평가에서도 통과율 100%(102/102)였다.

## 4. 구현하면서 정한 것

설계안 v3 원문을 읽지 못한 채 구현 지시문을 바탕으로 정했다. 원문과 다르면 고친다. 자세한 계약은 backend 저장소의 `docs/v3/CONTRACT.md`와 `docs/v3/RUNTIME.md`에 있다.

- **근거 ID 형식.** `종류:이름공간:키@판` 꼴로 정했다(예: `law:폐기물관리법:제17조@2026-11-12`). ID를 만드는 코드는 한 파일(`app/v3/ids.py`)에 모았다.
- **모델이 숫자를 쓰지 못하게 하는 방법.** 모델은 값을 직접 적지 않고, 코드가 만든 claim 목록에서 ID만 고른다. 목록에 없는 ID를 쓰면 거부한다. 검증기는 그다음에 한 번 더 본다.
- **핵심 코드는 표준 라이브러리만 쓴다.** FastAPI, SQLAlchemy, MCP SDK는 가장자리 모듈에만 있다. 그래서 같은 서비스 함수를 표준 라이브러리 HTTP 서버(`python3 -m app.v3.devserver`)로도 띄울 수 있다.
- **Agent Framework는 선택 사항으로 뒀다.** 대화 고리(초안, 검증, 재작성, handoff)는 직접 구현했고, 모델 호출 계층만 Agent Framework로 바꿀 수 있는 어댑터를 뒀다. 설계는 Agent Framework로 두 에이전트를 만드는 것이므로 차이가 있다.
- **두 에이전트는 판단 도구를 같은 프로세스에서 직접 부른다.** MCP 서버는 같은 도구를 밖으로 내놓는 용도로 따로 있다. MCP를 거치는 호출은 확인하지 못했다.
- **인증은 역할 할당 권한이 없어 키 방식이다.** 키는 Key Vault에만 둔다.
- **PostgreSQL과 AI Search는 Central US에 있다.** East US 2에서 두 서비스를 만들 수 없었다.
- **호스팅 대안.** Container Apps를 쓸 수 없으면 App Service로 간다. 리비전이 없어 되돌리기가 약하다.
- **업체당 대화는 하나다.** 한 업체로 가는 흐름을 한 대화에 모으고, 받지 않는 흐름은 그 대화 안에서 흐름 단위로 뺀다.
- **측정값이 없으면 확정하지 않는다.** 사진 추정 오염 비율과 담당자가 답한 수분만으로는 매입 기준 충족을 조건부로 둔다.
- **합의 뒤 조건이 바뀌면 승인을 막는다.** 업체가 기준표를 바꾸면 같은 대화에서 다시 협상하고, 배출 기업의 자료가 바뀌면 진단을 새로 해야 한다.
- **탄소는 참고 값이다.** 배정은 월 순비용으로만 고른다. 포장재 배출계수가 없어 탄소 합계는 "확인 필요"로 나온다.
- **가격조사 값은 참고 시세로만 보여 준다.** 손익 계산에는 업체 매입 기준표의 단가만 쓴다.

## 5. 가정값과 확인하지 못한 값

- 현행 처리 단가(혼합 소각), 등급별 오염도·수분 상한, 우회 계수, 운행 단가, 폐플라스틱 배출계수는 **팀 가정값**이다. 화면에 "가정값"으로 표시된다. 공식 출처로 바꿔야 한다.
- 배출계수(소각, 재활용), 공개 처리 단가, 순환자원 인정 고시, 시행령과 별표는 공식 출처를 확인하지 못해 넣지 않았다.
- 가격조사 값은 자원순환정보시스템 통계 화면에서 읽었고, 책자 PDF와 대조하지 못했다.
- 사례 50건의 기대값은 전문가 검토 전의 초안이다.

## 6. 알려진 문제

- **시연용 인증.** 기본 인증은 요청 헤더의 조직 ID를 그대로 믿는다. 공개 주소에 그대로 두면 조직 경계가 지켜지지 않는다. 조직별 토큰 모드를 켜거나 Entra에 연결해야 한다.
- **Prompt Shields가 연결돼야 주입 탐지가 동작한다.** 지금은 연결되지 않아 문서를 검사 없이 받는다. 문서의 글은 모델 입력에 들어가지 않고, 추출한 값은 사람이 확인한 뒤에만 근거가 된다.
- **담당자가 직접 넣는 이름은 모델 입력에 그대로 들어간다.** 흐름 이름이나 혼입물 이름에 지시문을 넣을 수 있다. 나가는 숫자와 조건은 검증기와 가드레일이 막는다.
- **조항 검색은 낱말 일치다.** 관련성이 낮은 조항이 잡힐 수 있어, 규정 검토 결과는 모두 "담당자 확인"으로 나온다.
- **최적안은 운송비를 목적 함수에 넣지 않는다.**
- 그 밖의 문제는 backend 저장소의 `docs/v3/review-rules.md`에 있다.

## 7. 다음에 할 일

1. 구독 관리자에게 공급자 등록(Microsoft.App, Microsoft.Maps, Microsoft.Fabric)과 GPU 할당량을 요청한다. 안 되면 App Service 대안으로 배포한다.
2. 배포한 뒤 실제 모델(Foundry gpt-5-mini)로 시연 시나리오와 형식 준수 시험을 돌린다. 통과율이 낮으면 프롬프트와 스키마를 고친다.
3. 설계안 v3 원문과 이 구현의 계약을 대조한다(근거 ID 형식 7.2, 대화 시퀀스 4.3과 4.4, 도구 목록 8장).
4. 가정값을 공식 출처로 바꾸고, 사례 50건을 전문가에게 검토받는다.
5. 탐지 모델을 Azure ML로 옮기고 두 엔드포인트를 배포한다.
